## 📌 Commit Message Rules（コミットメッセージ規則）

当プロジェクトでは、開発効率と履歴の可読性向上のため  
**Conventional Commits** に基づいた以下のルールを採用しています。

### 🚀 feat: 新しい機能の追加
例：
- `feat: プレイヤー移動処理を追加`
- `feat: 敵AIの追跡ロジックを実装`

### 🐛 fix: バグ修正
例：
- `fix: マップ衝突判定が抜ける問題を修正`
- `fix: UI が更新されない不具合を修正`

### 🧹 refactor: コード改善（挙動は変更しない）
例：
- `refactor: Player クラスの責務を整理`
- `refactor: MapLoader の重複コードを削除`

### 📝 docs: ドキュメント更新
例：
- `docs: README に環境構築手順を追加`

### 🎨 style: フォーマット修正（動作に影響なし）
例：
- `style: コード全体のフォーマットを統一`

### 🧪 test: テストコード追加・修正
例：
- `test: プレイヤー移動の単体テストを追加`

### 🛠 chore: その他の雑務
例：
- `chore: .gitignore を更新`
- `chore: ビルド設定を改善`

---

## 🔖 基本原則
- **1コミット1機能（または1修正）**
- **機能追加は feat、バグ修正は fix を必ず使用する**
- **コミット内容がわかる、短く明確なメッセージを書く**

---

## 🛠 Pull 前に必ず Build

他ブランチからコードを取り込む前に、必ずローカルでビルドを行い、  
問題なくコンパイルできる状態であることを確認してください。

- `git pull` 前にビルド  
- コンフリクトが発生した場合は手動で解決  
- 動作確認後に commit / push
